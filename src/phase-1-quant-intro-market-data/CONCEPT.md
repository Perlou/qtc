## 1. 什么是量化交易

### 1.1 定义

**量化交易（Quantitative Trading）** 是用数学模型和计算机程序来制定并执行投资决策的方法。它的核心是把一个交易想法变成：

- **可验证**：能在历史数据上检验它是否有效
- **可重复**：同样的输入永远得到同样的决策
- **可执行**：程序自动生成订单，不受情绪干扰

> 💡 **比喻**：主观交易像一位经验丰富的大厨凭手感做菜；量化交易像把这道菜写成精确到克的菜谱，并做成自动化厨房。菜谱可以被检验、改进、批量复制，但如果菜谱本身是错的，自动化厨房会把错误放大一千倍。

### 1.2 Alpha 与 Beta

投资收益可以拆成两部分：

$$
R_p = \alpha + \beta \cdot R_m + \varepsilon
$$

| 符号 | 含义 |
|---|---|
| $R_p$ | 你的组合收益 |
| $R_m$ | 市场收益（如沪深 300） |
| $\beta$ | 组合对市场涨跌的敏感度。$\beta = 1$ 表示市场涨 1%，组合也涨 1% |
| $\alpha$ | 与市场无关的超额收益，体现真正的能力 |
| $\varepsilon$ | 随机噪声 |

- **Beta 收益**是"随大流"的收益，买指数基金就能获得，成本极低
- **Alpha 收益**是稀缺的，量化研究员的核心工作就是**寻找可持续的 Alpha**，同时控制不想要的风险暴露

### 1.3 量化研究的基本骨架

所有量化策略，无论多复杂，都离不开这四步（`01-quant-trading-overview.py` 第五部分）：

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  数据    │───►│  信号    │───►│  持仓    │───►│  净值    │
│  Data    │    │  Signal  │    │ Position │    │   NAV    │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
  价格、财报      今天的判断      明天的仓位      收益累积
                               signal.shift(1)  (1+r).cumprod()
```

```python
signal   = (close > close.rolling(60).mean()).astype(int)   # 今天收盘后才知道
position = signal.shift(1).fillna(0)                         # 最早明天才能持仓
returns  = position * close.pct_change()                     # 持仓 × 标的收益
nav      = (1 + returns).cumprod()                           # 净值
```

⚠️ **`shift(1)` 是量化新手最重要的一行代码**。在课程示例里，沪深 300 的 60 日均线策略（2018–2024）正确写法总收益约 +21%，忘记 `shift` 的错误写法收益超过 +400%。差距全部来自"用今天的收盘价决定今天的持仓"这一未来信息。

### 1.4 量化研究流程

```
假设 → 数据 → 信号 → 回测 → 样本外验证 → 模拟盘 → 小资金实盘 → 监控归因 → 迭代/下线
 ▲                                                                              │
 └──────────────────────────────────────────────────────────────────────────────┘
```

两条铁律：

1. **先有经济逻辑，再有代码**。"为什么这个规律会存在？谁在亏钱给我？"回答不了这个问题的策略，大概率只是对历史噪声的拟合
2. **大多数想法会失败**。成熟的研究员会认真记录失败的想法，因为它们和成功的想法一样有价值

### 2.2 策略类型全景

| 类型 | 持仓周期 | 资金容量 | 主要依赖 |
|---|---|---|---|
| 高频 / 做市 | 毫秒~分钟 | 小 | 速度、微观结构 |

| 机器学习选股 | 天~周 | 中 | 数据与模型 |

## 3. A 股市场结构

### 3.1 交易所与板块

```
                         A 股市场
          ┌─────────────────┼─────────────────┐
     上海证券交易所     深圳证券交易所      北京证券交易所
     ┌─────┴─────┐      ┌─────┴─────┐            │
   沪市主板   科创板   深市主板   创业板        北交所
   600/601/   688/689  000/001/   300/301    8/4/92 开头
   603/605             002/003
```

| 板块 | 定位 | 涨跌幅限制 | 投资者门槛 |
|---|---|---|---|
| 沪深主板 | 大型成熟企业 | ±10% | 无 |
| 创业板 | 成长型创新企业 | ±20% | 有资产和经验要求 |
| 科创板 | 硬科技企业 | ±20% | 有资产和经验要求 |
| 北交所 | 创新型中小企业 | ±30% | 有资产和经验要求 |

> 投资者门槛的具体要求以交易所和券商最新规定为准。

### 3.2 证券代码

代码本身就携带了信息，量化程序经常要根据代码判断板块：

```python
def board_of(code: str) -> str:
    if code.startswith(("688", "689")):
        return "科创板"
    if code.startswith(("300", "301")):
        return "创业板"
    if code.startswith(("8", "4", "92")):
        return "北交所"
    return "沪市主板" if code.startswith("6") else "深市主板"
```

不同数据源的代码格式不同：AKShare 用 `600519`，Tushare 用 `600519.SH`，新浪接口用 `sh600519`。**统一代码格式是数据工程的第一步**。

### 3.3 指数与 ETF

- **指数**：按规则计算的一个数字，代表一篮子股票的整体表现，**不能直接买卖**。常用宽基指数：

  | 代码 | 名称 | 含义 |
  |---|---|---|
  | 000300 | 沪深 300 | 沪深两市市值最大、流动性最好的 300 只 |
  | 000905 | 中证 500 | 沪深 300 之后的 500 只中盘股 |
  | 000852 | 中证 1000 | 中证 500 之后的 1000 只小盘股 |
  | 399006 | 创业板指 | 创业板代表性股票 |

- **ETF**：跟踪指数的基金，可以像股票一样在交易所买卖。指数代表"理论收益"，ETF 代表"实际可获得的收益"（扣除管理费，存在跟踪误差）

- **指数成分会定期调整**（沪深 300 每半年一次）。用今天的成分股回测历史，会产生幸存者偏差（见第 12 节）

## 4. A 股交易规则

### 4.1 交易时段

```
09:15 ─ 09:25   开盘集合竞价（09:20 后不可撤单）
09:30 ─ 11:30   上午连续竞价
13:00 ─ 14:57   下午连续竞价
14:57 ─ 15:00   收盘集合竞价（不可撤单）
```

- **集合竞价**：一段时间内集中收集订单，按"成交量最大"原则确定一个统一成交价
- **连续竞价**：订单实时按"价格优先、时间优先"撮合

📌 日线的**开盘价来自开盘集合竞价**，**收盘价来自收盘集合竞价**。回测中"以收盘价成交"意味着信号必须在 14:57 之前算好，并在收盘集合竞价中下单。用当日收盘价计算信号、又以同一个收盘价成交，是一种隐性的未来函数。

### 4.2 T+1

**当天买入的股票，下一个交易日才能卖出**。

- 股票：T+1
- 部分 ETF（跨境、债券、黄金、货币 ETF）：T+0
- 期货、加密货币：T+0

影响：

1. 日内反转、日内止损在股票上无法直接实现
2. 回测引擎要记录"可卖数量"，当日买入部分不可卖
3. 想做日内策略，可以选择 T+0 的品种

### 4.3 涨跌停

$$
\text{涨停价} = \text{Round}\big(P_{\text{prev}} \times (1 + L)\big), \quad
\text{跌停价} = \text{Round}\big(P_{\text{prev}} \times (1 - L)\big)
$$

| 符号 | 含义 |
|---|---|
| $P_{\text{prev}}$ | 前收盘价 |
| $L$ | 涨跌幅限制比例（主板 10%，创业板/科创板 20%，北交所 30%） |
| $\text{Round}$ | **四舍五入**到 0.01 元 |

两个容易出错的细节：

**① 舍入方式**。Python 的 `round()` 是"银行家舍入"，再叠加浮点误差，会和交易所规则差 1 分钱：

```python
>>> 10.05 * 1.1
11.055000000000001
>>> round(11.055, 2)
11.05              # ❌ 交易所规则是 11.06

from decimal import Decimal, ROUND_HALF_UP
>>> float(Decimal("11.055").quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))
11.06              # ✅
```

**② 规则随时间变化**。例如沪深主板 ST / \*ST 股票的涨跌幅限制，在 **2026-07-06 之前为 ±5%，之后调整为 ±10%**。回测历史时必须用**当时**的规则：

```python
def main_board_limit(is_st: bool, trade_date: str) -> float:
    if is_st and pd.Timestamp(trade_date) < pd.Timestamp("2026-07-06"):
        return 0.05
    return 0.10
```

此外，注册制下新股上市前 5 个交易日不设涨跌幅限制（北交所为上市首日）。

**对回测的影响**：涨停时往往只有卖单在排队，买不进；跌停时卖不出。回测中"在涨停价买入"通常不应假设成交，"在跌停时止损"也不能假设成交。

### 4.4 交易单位

| 板块 | 买入 | 卖出 |
|---|---|---|
| 主板、创业板 | 100 股（1 手）的整数倍 | 可一次性卖出零股 |
| 科创板 | 最少 200 股，超出部分以 1 股递增 | 同上 |

价格最小变动单位为 0.01 元。

📌 10 万元买不了 1 手股价 1500 元的贵州茅台（需要 15 万元）。小资金很难精确执行多因子组合的目标权重，回测时必须做整数手取整。

## 5. 交易成本

### 5.1 成本构成

| 费用 | 方向 | 费率（编写时） |
|---|---|---|
| 佣金 | 买 + 卖 | 券商协商，常见万 1 ~ 万 3，**最低 5 元**（部分券商免五） |
| 印花税 | **仅卖出** | 0.05%（2023-08-28 起） |
| 过户费 | 买 + 卖 | 0.001% |
| 滑点 | 买 + 卖 | 不是费用，而是实际成交价与预期价格的差 |

> 费率会调整，实盘前请核对交易所和券商的最新标准。

```python
def trade_cost(price, shares, side, rate=0.00025, min_comm=5.0):
    amount = price * shares
    commission = max(amount * rate, min_comm)
    stamp = amount * 0.0005 if side == "sell" else 0.0
    transfer = amount * 0.00001
    return commission + stamp + transfer
```

### 5.2 成本的量级

| 交易金额 | 买卖一轮费率（佣金万 2.5，最低 5 元） |
|---|---|
| 2,000 元 | 约 0.55% |
| 10,000 元 | 约 0.15% |
| 20,000 元以上 | 约 0.10% |

**换手率决定了成本拖累**：

$$
\text{年化成本拖累} \approx \text{年换手次数} \times \text{单次买卖一轮成本}
$$

一个每周调仓一次的策略：$52 \times 0.1\% \approx 5.2\%$ 每年，**还没算滑点**。很多回测漂亮的高频调仓策略，扣完成本就不赚钱了。这就是为什么 Phase 4 要求所有回测都做成本敏感性分析。

| 接口 | 成交量 | 成交额 | 涨跌幅 |

**入库前必须统一单位**。课程统一格式：

```
index:   DatetimeIndex（名为 date）
columns: open, high, low, close（元）, volume（股）, amount（元）
```

`src/utils/data.py` 中的 `get_stock_daily` 等函数会自动完成标准化，并提供：

1. **Parquet 缓存**：第一次下载后存本地，之后直接读取
2. **多数据源回退**：东方财富失败时尝试新浪
3. **离线回退**：网络失败或 `QTC_OFFLINE=1` 时生成合成数据，并打印 `⚠️ 使用合成数据`

```python
merged = pd.DataFrame({"ak": ak_df["close"], "ts": ts_df["close"]}).dropna()
```

## 7. OHLCV 与 K 线

### 7.1 OHLCV

| 字段 | 含义 |
|---|---|
| Open | 开盘价 |
| High | 最高价 |
| Low | 最低价 |
| Close | 收盘价（最重要，绝大多数指标基于它计算） |
| Volume | 成交量（股） |
| Amount | 成交额（元） |

**必然成立的逻辑关系**（数据质量检查的基础）：

$$
\text{Low} \le \min(\text{Open}, \text{Close}) \le \max(\text{Open}, \text{Close}) \le \text{High}, \quad \text{Volume} \ge 0
$$

**成交均价（VWAP）**：

$$
\text{VWAP} = \frac{\text{Amount}}{\text{Volume}}
$$

VWAP 是机构衡量执行质量的基准，Phase 11 会详细讲解。

### 7.2 K 线（蜡烛图）

```
     阳线（收 > 开）            阴线（收 < 开）
          │ ← 上影线                │
        ┌─┴─┐ ← 收盘              ┌─┴─┐ ← 开盘
        │   │ ← 实体（红）        │███│ ← 实体（绿）
        └─┬─┘ ← 开盘              └─┬─┘ ← 收盘
          │ ← 下影线                │
```

- **A 股习惯红涨绿跌**，与欧美相反
- **长上影线**：盘中冲高被打回，上方抛压重
- **长下影线**：盘中下探被拉回，下方承接强
- **十字星**：实体很小，多空僵持

⚠️ K 线形态有没有预测力，要用数据检验，而不是凭感觉。`05-ohlcv-candlestick.py` 统计了各形态出现后的次日收益：计算"次日收益"作为**研究标签**时使用 `shift(-1)` 是合理的，但**交易信号**里绝不能出现 `shift(-1)`。

### 7.3 重采样

日线转周线时，每个字段的聚合方式不同：

```python
rule = {"open": "first", "high": "max", "low": "min",
        "close": "last", "volume": "sum", "amount": "sum"}
weekly = daily.resample("W-FRI").agg(rule).dropna(subset=["close"])
```

⚠️ `W-FRI` 用周五作为标签。如果数据只到周二，最后一根周线的标签仍是周五（一个还没到的日期）。回测时如果在"标签日"使用这根周线，就用到了不完整或未来的信息。

## 8. 除权除息与复权

这是 Phase 1 最重要、也最容易出错的概念。

### 8.1 为什么股价会"跳水"

公司分红送转后，交易所会在**除权除息日**下调股价，使投资者的总财富不变：

$$
P_{\text{ref}} = \frac{P_{\text{prev}} - D}{1 + S}
$$

| 符号 | 含义 |
|---|---|
| $P_{\text{ref}}$ | 除权（息）参考价，即除权日的"理论开盘基准" |
| $P_{\text{prev}}$ | 股权登记日收盘价 |
| $D$ | 每股现金红利（元）。数据源通常给"每 10 股派 X 元"，要除以 10 |
| $S$ | 每股送转股比例。"10 送 3 转 2"即 $S = 0.5$ |

> 🍕 **比喻**：披萨切成 8 块，每块 10 元。分红像先拿出 1 元现金给你，披萨只剩 9 元/块；送转像把 8 块切成 16 块，每块 5 元但块数翻倍。总价值不变，"每块价格"变了。

**真实例子**（中国神华 601088，2024-07-08 除息，每股派 2.26 元）：

| 前收盘 | 参考价 | 当日收盘 | 不复权涨跌 | 真实涨跌 |
|---|---|---|---|---|
| 45.10 | 42.84 | 43.38 | **−3.81%** | **+1.26%** |

如果直接用不复权价格计算收益，会把每次分红都误认为"亏损"。中国神华 2022–2024 年，不复权价格的区间收益约 +91%，考虑分红再投资的真实收益约 +137%：**不复权价格少算了约 46 个百分点**。

### 8.2 复权因子

**等比复权因子**在每个除权日"跳一步"：

$$
F_t = \prod_{\tau \le t,\ \tau \in \text{除权日}} \frac{P_{\text{prev},\tau}}{P_{\text{ref},\tau}}
$$

$$
P^{\text{hfq}}_t = P_t \times F_t, \qquad P^{\text{qfq}}_t = P_t \times \frac{F_t}{F_T}
$$

| 符号 | 含义 |
|---|---|
| $F_t$ | $t$ 日的后复权因子，上市首日为 1 |
| $P_t$ | $t$ 日不复权价格 |
| $P^{\text{hfq}}_t$ | 后复权价格：以上市首日为基准 |
| $P^{\text{qfq}}_t$ | 前复权价格：以最新日 $T$ 为基准，最新价格等于真实价格 |

```python
def manual_adj_factor(raw: pd.DataFrame, div: pd.DataFrame) -> pd.Series:
    step = pd.Series(1.0, index=raw.index)
    for _, d in div.iterrows():
        i = raw.index.get_indexer([d["除权除息日"]])[0]
        prev_close = raw["close"].iloc[i - 1]
        ref = (prev_close - d["每股派息"]) / (1 + d["每股送转"])
        step.iloc[i] = prev_close / ref
    return step.cumprod()
```

`06-adjusted-prices.py` 用这段代码手工计算了中国神华的复权因子，与新浪数据源的复权因子差异在 $10^{-14}$ 量级，即完全一致。

### 8.3 加减法复权 vs 等比复权

这是课程在真实数据上发现的一个重要问题：

| 方式 | 计算 | 除权日收益 |
|---|---|---|
| **等比复权** | 历史价格 × 比例因子 | ✅ 与真实收益一致 |
| **加减法复权** | 历史价格 ± 累计分红金额 | ❌ 有偏差 |

AKShare 东方财富接口（`stock_zh_a_hist` 的 `adjust="qfq"/"hfq"`）使用的是**加减法复权**：除息日"复权价 − 不复权价"的变化量恰好等于每股分红金额。后果：

| 除息日 | 真实收益 | 等比复权 | 东财后复权 | 东财前复权 |
|---|---|---|---|---|
| 2022-07-11 | −6.18% | −6.18% | −4.06% | −9.16% |
| 2024-07-08 | +1.26% | +1.26% | +0.85% | +1.44% |

累积下来，区间总收益差异巨大（课程示例中，东财前复权的区间收益比等比复权高出一倍多）。高分红股票的长历史加减法前复权价格甚至可能出现**负数**。

✅ **结论**：计算收益使用等比复权。课程提供了 `utils.data.get_stock_daily_adj()`，返回不复权价格加等比后复权因子，以及 `adj_close = close × adj_factor`。

### 8.4 工程最佳实践

```
┌──────────────────────────────────────────────────────────┐
│  存储：不复权 OHLCV + 后复权因子（两张表，只追加不修改）  │
└───────────────────────────┬──────────────────────────────┘
              ┌─────────────┴─────────────┐
              ▼                           ▼
     计算收益 / 信号               模拟撮合
     adj_close = close × F         不复权价格（涨跌停、整数手、金额）
```

**为什么不直接存前复权价格？**

1. 前复权价格每次分红后都会**整体改变**，今天跑的回测和下个月跑的结果不同，无法增量更新
2. 在历史 $t$ 日"看到"的前复权价格，包含了 $t$ 日之后的分红信息，**是隐性的未来函数**。例如用前复权价格判断"股价是否低于 5 元"，历史上那一天的真实价格可能是 8 元

## 9. 交易日历、停牌与数据对齐

### 9.1 三种"天"

| 概念 | 2024 年天数 | 说明 |
|---|---|---|
| 自然日 | 366 | 包含周末和节假日 |
| 工作日 | 262 | 周一到周五 |
| **交易日** | **242** | 交易所实际开市的日子 |

- "持有 20 个交易日" ≠ "持有 20 天" ≠ "持有 4 周"
- 年化计算常用 252 个交易日，A 股实际每年 240–250 天
- 月度调仓日（如"每月最后一个交易日"）必须用交易日历计算

```python
cal = pd.to_datetime(ak.tool_trade_date_hist_sina()["trade_date"])
s = pd.Series(cal, index=cal)
month_ends = s.groupby(s.index.to_period("M")).last()
```

### 9.2 停牌

**交易日历上有、但个股数据中没有的日期就是停牌**。

```python
window = cal[(cal >= start) & (cal <= end)]
suspended = window.difference(stock_df.index)
```

真实例子：万科 A（000002）在 2015-12-21 至 2016-07-01 停牌 130 个交易日，复牌后连续跌停。

对回测的影响：

1. 停牌期间**不能交易**，回测引擎必须拒绝停牌日的订单
2. 停牌期间的涨跌在**复牌日集中释放**，不能忽略或平摊
3. 长期停牌是流动性风险：你想卖也卖不掉

### 9.3 多资产对齐

多只股票的日期索引往往不一致（停牌、上市时间不同、退市）。正确做法是 **`reindex` 到交易日历**，显式暴露所有缺失，再按原因分别处理：

| 缺失原因 | 价格处理 | 收益 / 交易处理 |
|---|---|---|
| 尚未上市 | 保持 NaN | 不在可投资范围内 |
| 停牌 | `ffill` | 当日收益为 0，禁止交易 |
| 已退市 | 保持 NaN | 按退市价格清算，**不能让它凭空消失** |
| 数据错误 | 查明原因 | 先修数据 |

### 9.4 缺失值处理的铁律

> **金融时间序列只能用过去填充未来，绝不能用未来填充过去。**

| 方法 | 停牌日价格 | 问题 |
|---|---|---|
| `fillna(0)` | 0 | 收益变成 −100% 和 +∞ |
| `bfill()` | 复牌后的价格 | **未来函数**：停牌日"知道"了未来价格 |
| `interpolate()` | 插值 | **未来函数** + 凭空制造平滑走势 |
| `ffill()` ✅ | 停牌前最后价格 | 停牌日收益为 0，复牌日体现累计涨跌 |

## 10. 数据存储

### 10.1 CSV vs Parquet

课程实测（300 只股票 × 10 年日线，约 78 万行）：

| 格式 | 体积 | 全量读取 | 只读 3 列 |
|---|---|---|---|
| CSV | 53 MB | 0.14 s | 0.08 s |
| Parquet (snappy) | 16 MB | 0.014 s | 0.010 s |

**Parquet** 是列式存储格式：

```
行式（CSV）：  [日期,代码,开,高,低,收,量] [日期,代码,开,高,低,收,量] ...
列式（Parquet）：[日期,日期,日期...] [代码,代码...] [收,收,收...] ...
                 ↑ 同一列的数据放在一起 → 压缩率高，只读需要的列
```

Parquet 还保存了数据类型，日期读回来仍是 `datetime`，不需要每次重新解析。

### 10.2 分区

```
warehouse/stock_daily/
├── year=2023/data.parquet
├── year=2024/data.parquet
└── year=2025/data.parquet
```

查询"2024 年的数据"时只读一个文件。分区原则：

- 按**最常用的过滤条件**分区：日线按年，分钟线按日期，tick 按日期 + 品种
- 分区不要太碎，每个文件至少几 MB
- 原始数据（raw）和处理后数据（processed）分开存放

### 10.3 DuckDB

**DuckDB** 是嵌入式的分析型数据库，可以理解为"分析领域的 SQLite"：不需要启动服务，直接用 SQL 查询 Parquet 文件和内存中的 pandas DataFrame。

```python
import duckdb

duckdb.sql("""
    SELECT symbol, year,
           arg_max(close, date) / arg_min(close, date) - 1 AS yearly_return
    FROM read_parquet('warehouse/stock_daily/*/*.parquet', hive_partitioning = true)
    GROUP BY symbol, year
""").df()
```

| 场景 | 推荐工具 |
|---|---|
| 数据比内存大、复杂 SQL（窗口函数、多表 JOIN） | DuckDB |
| 数据已在内存、需要灵活的逐步变换 | pandas |

### 10.4 增量更新

```python
def upsert(existing, new, keys=("symbol", "date")):
    merged = pd.concat([existing, new])
    return merged.drop_duplicates(subset=list(keys), keep="last").sort_values(list(keys))
```

要点：

1. **主键去重保证幂等**：重复运行任意次，结果都一样
2. **往回多取几天**：数据源可能修正最近几天的数据
3. **记录元信息**：数据来源、下载时间、覆盖范围。研究结论要能追溯到具体的数据版本
4. **复权价格不能增量更新**：只存不复权价格加复权因子

## 11. 期货与加密货币数据

### 11.1 期货基础

**期货**是约定在未来某个日期，按约定价格交割标的物的标准化合约。

| 要素 | 螺纹钢 RB 示例 |
|---|---|
| 合约代码 | RB2505（2025 年 5 月到期） |
| 合约乘数 | 10 吨/手 |
| 保证金 | 合约价值的约 10%（交易所和期货公司设定，会调整） |

**杠杆**：

$$
\text{杠杆倍数} = \frac{1}{\text{保证金比例}}, \qquad
\text{保证金收益率} = \text{价格变动率} \times \text{杠杆倍数}
$$

保证金 10% 即 10 倍杠杆：价格下跌 5%，保证金亏损 50%；下跌 10%，保证金亏光，会被要求追加保证金或强行平仓。

### 11.2 主力合约与换月

同一时间有多个月份的合约在交易，资金集中在**主力合约**上，并会随到期临近切换到下一个合约。**主力连续**就是把每天的主力合约价格拼接起来的序列。

⚠️ **换月跳空**：切换日新旧合约之间存在价差，主力连续在这一天的"收益"包含这个价差，不是真实可获得的收益。课程用 2024 年螺纹钢数据验证：

| 切换日 | 合约 | 主力连续收益 | 真实持仓收益 |
|---|---|---|---|
| 2024-04-03 | RB2405 → RB2410 | +0.00% | −1.23% |
| 2024-09-03 | RB2410 → RB2501 | −0.91% | −2.30% |
| 2024-12-06 | RB2501 → RB2505 | +0.95% | −0.90% |

解决思路与股票复权相同（Phase 5 实现）：

- **价差调整**：历史价格整体平移换月价差（类似加减法复权）
- **比例调整**：历史价格整体乘以新旧合约价格比（类似等比复权）
- **最真实**：直接用单个合约数据，回测中显式模拟换月交易

### 11.3 加密货币数据

**ccxt** 统一了上百家交易所的 API：

```python
import ccxt
ex = ccxt.okx()
bars = ex.fetch_ohlcv("BTC/USDT", "1d", limit=300)   # [[毫秒时间戳, 开, 高, 低, 收, 量], ...]
```

数据特点：

1. **7×24 小时交易**，没有周末和节假日，年化用 365 天
2. K 线时间是 **UTC**，日线在北京时间早上 8 点切换
3. **最后一根 K 线通常还没收盘**，研究时应丢弃
4. 单次请求有条数上限，长历史需要用 `since` 参数分页获取

> ⚠️ **合规提示**：中国内地监管部门已明确虚拟货币相关业务活动属于非法金融活动。课程只获取公开行情数据用于学习研究，请遵守所在地法律法规。

### 11.4 三个市场对比

| | A 股 | 国内期货 | 加密货币 |
|---|---|---|---|
| 交易时间 | 工作日约 4 小时 | 日盘 + 夜盘 | 7×24 小时 |
| T+0 / T+1 | T+1 | T+0 | T+0 |
| 做空 | 融券（受限） | 自由做空 | 合约做空 |
| 涨跌停 | 有 | 有 | 无 |
| 年化天数 | ≈ 252 | ≈ 252 | 365 |
| 主要数据难点 | 复权、停牌、退市 | 换月、夜盘归属 | 交易所差异、时区 |

📌 **夜盘归属**：期货夜盘（如 21:00 开始）属于**下一个交易日**，周五夜盘归属于下周一。合并股票和期货数据时要特别注意对齐。

**年化波动率**：

$$
\sigma_{\text{年}} = \sigma_{\text{日}} \times \sqrt{N}
$$

$N$ 为一年的交易天数。加密货币如果错误地用 $N = 252$ 而不是 365，会低估约 17% 的波动率（$1 - \sqrt{252/365} \approx 0.17$）。

## 12. 数据偏差与数据质量

### 12.1 偏差全景

| 偏差 | 典型错误 | 正确做法 |
|---|---|---|
| **幸存者偏差** | 用今天的股票列表回测 10 年前 | 使用含退市股的历史股票池 |
| **前视偏差** | 用 3 月 31 日"报告期"对齐财报 | 按实际公告日对齐 |
| | 用当日收盘价算信号并以收盘价成交 | 信号次日执行 |
| | 用前复权价格做绝对价格判断 | 使用当时的真实价格 |
| **成分股偏差** | 用今天的沪深 300 成分回测 | 使用历史时点成分股 |
| **选择偏差** | 只研究"大家都在讨论"的股票 | 预先定义股票池规则 |
| **数据窥探** | 反复试参数直到回测好看 | 记录尝试次数，做样本外检验 |

共同点：**让回测看起来很好，实盘却赚不到钱**。

### 12.2 幸存者偏差实验

`10-data-biases-quality.py` 模拟了 1000 只**真实期望收益完全相同**的股票，累计下跌 80% 即退市：

| 统计口径 | 10 年平均总收益 |
|---|---|
| ✅ 全部股票（含退市） | 约 +116% |
| ❌ 只看幸存者 | 约 +256% |

股票本身没有任何区别，只是加上"今天还活着"这个条件，就筛掉了历史上最差的那批，凭空制造出 140 个百分点的收益。

A 股的特殊之处：

- 近年退市制度改革后，退市数量明显增加，偏差更严重
- 小市值、低价股策略对幸存者偏差尤其敏感
- 免费数据源的"股票列表"通常不含退市股，需要单独获取退市名单（`ak.stock_info_sh_delist()`、`ak.stock_info_sz_delist()`）

### 12.3 前视偏差的隐蔽形式

最隐蔽的一种：**用全样本统计量做标准化**。

```python
z_bad  = (price - price.mean()) / price.std()                           # ❌ 用了未来数据
z_good = (price - price.expanding(20).mean()) / price.expanding(20).std()  # ✅ 只用过去
```

课程在 500 条随机游走（理论上没有任何可预测性）上做均值回归：

| 方法 | 平均收益 | 盈利路径占比 |
|---|---|---|
| ❌ 全样本 z-score | 约 +13.6% | 约 85% |
| ✅ 扩展窗口 z-score | 约 0% | 约 50% |

全样本均值"知道"整段行情的平均水平，因此在纯随机数据上也能制造稳定的虚假收益。**只看一条路径可能看不出来，必须用大量模拟才能看清偏差。**

其他隐蔽形式：

1. 用全样本拟合标准化器、PCA 或机器学习模型，再在同一段数据上回测
2. 用当前的行业分类、ST 状态、指数成分去筛选历史股票
3. 周线 `resample` 后，在周一就使用了"本周"的周线
4. 用到了数据供应商事后修正过的数据

### 12.4 数据质量检查清单

| # | 检查项 | 规则 |
|---|---|---|
| 1 | 重复主键 | (symbol, date) 唯一 |
| 2 | 价格缺失 | OHLC 无 NaN |
| 3 | 非正价格 / 负成交量 | 价格 > 0，成交量 ≥ 0 |
| 4 | OHLC 逻辑 | low ≤ open/close ≤ high |
| 5 | 涨跌幅越界 | 不复权收益不超过板块限制（排除除权日） |
| 6 | 复权跳变 | 复权收益不超过板块限制（否则复权因子可能有误） |
| 7 | 数据缺口 | 相邻记录间隔过长（长期停牌或数据缺失） |

处理流程：**发现 → 记录 → 查明原因 → 修复或剔除 → 在研究报告中披露**。检查函数只负责发现问题，判断需要结合分红、停复牌等其他数据。

## 13. 最佳实践与常见陷阱

### 13.1 最佳实践

1. **存原始数据，不存加工结果**：不复权价格加复权因子，原始数据只追加不修改
2. **统一数据格式**：代码、日期、单位在入库时统一
3. **交叉验证**：至少用两个数据源核对关键数据
4. **记录数据版本**：来源、下载时间、覆盖范围
5. **先审计数据，再研究策略**：每次拿到新数据，先跑质量检查
6. **规则按日期生效**：涨跌停比例、费率、交易制度都会变化，回测要用当时的规则

### 13.2 常见陷阱

| 陷阱 | 症状 | 解决 |
|---|---|---|
| 忘记 `shift(1)` | 回测收益好得离谱 | 信号次日执行 |
| 用不复权价格算收益 | 高分红股票收益被严重低估 | 用等比复权 `adj_close` |
| 用加减法复权算收益 | 除权日收益失真 | 用等比复权因子 |
| 用前复权价格做绝对价格判断 | 隐性未来函数 | 用当时的真实价格 |
| `fillna(0)` / `bfill` 填充价格 | 收益异常 / 未来函数 | `ffill`，并标记停牌 |
| 成交量单位不统一 | 成交额与均价对不上 | 入库时统一为"股" |
| 用 `round()` 算涨停价 | 差 1 分钱 | `Decimal` + `ROUND_HALF_UP` |
| 用今天的股票列表回测历史 | 幸存者偏差 | 含退市股的历史股票池 |
| 加密货币用 √252 年化 | 低估波动率 | 用 √365 |
| 使用未收盘的最后一根 K 线 | 信号不稳定 | 丢弃最后一根 |
